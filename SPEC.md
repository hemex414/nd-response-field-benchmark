## 3. Construction

### 3.1 Components

$$
V_{\text{raw}}(\mathbf u)=
\underbrace{\sum_{i=1}^{3} w_i\frac{u_i}{100}}_{\text{trend}}
+\underbrace{\sum_{i=1}^{3}\sum_{m=1}^{4} a_{im}\exp\!\Big(-\frac{(u_i-\mu_{im})^2}{2\sigma_{im}^2}\Big)}_{\text{1-D ripples}}
+\underbrace{\sum_{k=1}^{48} A_k\,\big[G_k(\mathbf u)+0.45\,G_k^{(2)}(\mathbf u)\big]}_{\text{3-D two-lobe islands}}
+\underbrace{\sum_{p=1}^{14} B_p\,G_p(\mathbf u)}_{\text{3-D negative pockets}}
+\underbrace{\sum_{c=1}^{5}\sum_{t=1}^{30} -D_c\,G_{c,t}(\mathbf u)}_{\text{3-D curved corridors}}
+\underbrace{\sum_{r=1}^{4} \varepsilon_r\prod_{i=1}^{3}\sin(2\pi u_i/\lambda_{ri}+\phi_{ri})}_{\text{3-D multiplicative ripples}}
$$

Here $G$ is an anisotropic 3-D Gaussian. Corridor centers follow the 3-D sinusoidal curve
$c_x(t)=x_0+a_x\sin(2\pi t/\ell_x+\phi_x)$ (similarly for $y$ and $z$), with $\sigma_c=2.8$.

### 3.2 Value mapping

$$
\hat V=\frac{V_{\text{raw}}-\min V_{\text{raw}}}{\max V_{\text{raw}}-\min V_{\text{raw}}},\qquad
V=100+60\,\hat V\in[100,160].
$$

The positive affine map preserves optimal trajectories, method rankings and feasibility. $\Delta V$ is normalized by the 60-unit range.

Machine-readable values are in `params.json`.

## 5. Reproduction and verification

```bash
cd public_field/code
python make_field.py --out ../data/canonical_3d_seed2026.npz --resolution 80 --seed 2026
sha256sum ../data/canonical_3d_seed2026.npz    # must match CHECKSUMS.txt
python audit_field.py                          # regenerate audit.json and figure
```

- The canonical file is uniquely determined by the seed and generator; other resolutions only change sampling, not the definition.
- If the hash differs, check the NumPy version and generator hash; do not edit the file manually.

## 6. Property audit (Gate G0, passed)

Audit grid: 3 dimension pairs × fixed values {10,30,50,70,90} = 15 2-D slices.

| Metric | Result | Threshold |
|---|---|---|
| Significant peaks per slice | 5–11 | ≥5 per slice |
| Full high-value lines (row/column std<1.2 and mean>80th percentile) | 0 | 0 |
| Cross-slice peak range | 118.98–158.44 | range ≥20 |
| Low-value corridor level (20th percentile) | 115.24–127.78 | overlaps low-peak interval |
| Additive fit $R^2$ | 0.8208 | ≤0.85 |
| Coverage of $\lvert$residual$\rvert>1$ | 60.5% | ≥50% |
| Largest low-value connected component per slice | 16.3–20.0% | 10–25% |
| Gate G0 | **passed** | — |

> This is an empirical audit, not a mathematical guarantee that every slice contains structure. Slices near the domain boundary are naturally sparser.

## 7. Interface

```python
from make_field import make_field
f = make_field(seed=2026, resolution=80)
V = f([50, 50, 50])            # -> array([...]) in [100,160]
S = f.slice("12", 50.0)        # u1-u2 slice (u3=50), 80x80
ax, G = f.axes, f.grid         # grid axes and values
f.save("canonical.npz")
```

- $N=3$ is the canonical instance. The N-D benchmark uses the same generator for each subset.
- The range [100,160] is a convention; a positive affine map to [0,1] or [0,100] preserves rankings.

## 8. Scope

1. The field is synthetic, dimensionless and has no physical background; it must not be interpreted as vibration, dB, or any physical quantity.
2. Its purpose is algorithm comparison, not physical prediction.
3. Slice properties are covered by the audit (15/15 passed), not by a pointwise reconstruction.
4. The generator contains no measured data or surrogate model.
5. Absolute values are not meaningful; report relative rankings, $\Delta V$, and percentages.

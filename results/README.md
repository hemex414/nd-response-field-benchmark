# Results Directory

This directory contains the 8×1000-case public-benchmark results, summary tables and timing matrix. All results were generated by scripts in `code/` with the same `evaluate.py` and the same time-indexed corridor.

Compact per-case results are tracked in `per_case/N*.csv.gz`; the full JSONL records are not tracked. `FINAL_BY_N.md`, `timing_single.csv`, `TEST_MATRIX.md` and `test_matrix.json` are also tracked.

## 1. Layout

```
results/
├─ FINAL_BY_N.md              # per-N summary: CoTra-J / best baseline / ΔJ / feasibility
├─ timing_single.csv          # single-case and batch=16 per-case times
├─ per_case/N1..N8.csv.gz     # compact per-case results for all methods
├─ TEST_MATRIX.md             # T1–T6 test matrix
├─ test_matrix.json
├─ E4_batch/
│  └─ N1..N8/
│     └─ cotra_j_batch.jsonl  # CoTra-J per-case records, one case per line
└─ E5_batch/
   └─ N1..N8/
      ├─ per_case_N<n>.jsonl  # merged per-case records for 11 baselines
      ├─ <method>.json        # full records for one method
      ├─ summary.json         # per-N summary
      ├─ merged_summary.json  # merged summary
      ├─ timing.csv           # per-N timing
      └─ run_manifest.json    # run parameters and environment
```

## 2. Per-case fields

CoTra-J (`cotra_j_batch.jsonl`) fields include:

| Field | Meaning |
|---|---|
| `case_id`, `N`, `subset`, `field_seed` | case identity; the field is generated from `(N, field_seed)`; `subset` selects state-dimension indices |
| `A`, `B`, `rates`, `TR` | start/end states, per-dimension rate limits, budget ratio |
| `J` | time-weighted vibration level (dimensionless) |
| `T`, `durations` | total duration and 8 segment durations |
| `feasible` | endpoint / rate / time-indexed corridor / total duration all satisfied |
| `endpoint_error`, `rate_violation`, `corridor_violation_time` | numeric feasibility checks |
| `points` | 9×N node coordinates |
| `runtime_s` | single-case wall-clock time |

Baseline records (`per_case_N<n>.jsonl` / `<method>.json`) use compatible fields and additionally include `time_alloc`, `time_alloc_applied`, and `repair_fac`.

## 5. Regenerate

```bash
# CoTra-J: N=1..8, 1000 cases each, batch=16
for n in 1 2 3 4 5 6 7 8; do
  python code/run_batch_cotra_j.py --n $n --batch 16 \
    --out results/E4_batch/N$n/cotra_j_batch.jsonl
done

# 11 baselines
for n in 1 2 3 4 5 6 7 8; do
  python code/run_batch.py --N $n \
    --methods fmm astar theta_star lattice rrt_star bit_star ga gd sa chomp random \
    --out results/E5_batch/N$n --workers 12 --batch-size 16
done

python code/merge_e5_cotra.py
```

## 6. Timing

`timing_single.csv` columns:

```
method,N,n,batch,workers,mean_s,median_s,min_s,max_s,device,feasible,status,note
```

- `batch=1`: single-case time; `batch=16`: per-case time for a batch of 16;
- grid methods at N≥4 are `grid_too_large`; Lattice is `too_slow` at N≥4; GD is `too_slow` at N=8;
- only absolute times are reported; no speed-up ratio is computed.

Full run parameters are in each `run_manifest.json`; environment requirements are in the repository README.
